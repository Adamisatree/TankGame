# 1.6.3 —— 桌面版启动崩溃（热修）

1.6.2 发出去之后，**所有桌面版用户双击图标都会崩**：

```
Error [ERR_REQUIRE_ESM]: require() of ES Module
D:\Program Files\TankGame\resources\app\shared\asset-guard.mjs
from D:\Program Files\TankGame\resources\app\electron\updater.cjs not supported
```

窗口一个都没出来。这一版只修这一件事，外加让这类事故**不可能再被漏测**。

---

## 一、根因

1.6.2 为了给「下载/安装守卫」写单元测试（不依赖 Electron 二进制），把它抽成了 ES 模块
`shared/asset-guard.mjs`。但 `electron/updater.cjs` 是 **CommonJS**（Electron 直接加载主进程文件，
必须是 CJS），里面用了同步 require：

```js
// v1.6.2 electron/updater.cjs:19
const assetGuard = require('../shared/asset-guard.mjs');
```

Electron 31 内置 **Node 20**，`require()` 一个 ES 模块会抛 `ERR_REQUIRE_ESM`。而这行在
**模块顶层**：`electron/main.cjs` 第 14 行 `require('./updater.cjs')` 时就会炸，
**任何窗口、任何 IPC 都还没建立**——所以应用不是「某个功能坏了」，是根本起不来；
也意味着**内置的自动更新器救不了**（它自己就在这个模块里）。

仓库里其余从 CJS 加载 `.mjs` 的地方（`update-core.mjs`、`lan-server.mjs`）本来就是
`await import(pathToFileURL(...))` 的动态导入，只有这次新增的守卫写成了 `require`。
全仓库确认**没有第二处**同类写法。

## 二、为什么测试没拦住

| 层面 | 情况 |
| --- | --- |
| `updatetest`（86 条） | 直接 import `shared/asset-guard.mjs` 测纯函数——测的是**修好的那段**，从不加载 `updater.cjs` |
| `desktop-test`（17 条） | 1.6.2 改成同样直接 import 守卫（因为「`updater.cjs` 会 `require('electron')`，本机没有二进制就加载不了」）——测试为了能跑，正好绕过了出事的那一行 |
| CI | 「Type-check and test」只跑 `typecheck / selftest / lantest / test:update`，**根本不跑 `desktop-test`** |
| 真机 | 打标签前没有装一次、双击一次 |

而且本机开发用的是 Node 22（`require(esm)` 已经默认开启，会「碰巧成功」），CI 用 Node 20 但从不执行
主进程代码——两边都看不见这个错误。

## 三、修复（2 个文件 + 1 个类型声明）

### 1. `electron/updater.cjs`：守卫改成惰性动态导入

```js
/**
 * v1.6.3 hotfix: this file is CommonJS, and require() of an ESM throws
 * ERR_REQUIRE_ESM on the Node 20 that Electron 31 ships — at module load,
 * before any window exists …
 */
let assetGuard = null;
async function loadGuard() {
  if (!assetGuard) {
    assetGuard = await import(pathToFileURL(join(__dirname, '..', 'shared', 'asset-guard.mjs')).href);
  }
  return assetGuard;
}
```

随之 `safeAssetName()` / `versionFileFor()` 变成 `async`，`ensureDownloaded()` 里加一个 `await`。
两个调用点（`ensureDownloaded`、`isAllowedAssetUrl`）本来就在 async 函数里。

### 2. `electron/main.cjs`：唯一的外部调用点补 `await`

```diff
-  const assetName = updater.safeAssetName(rawName);
+  const assetName = await updater.safeAssetName(rawName);
```

### 3. `shared/asset-guard.d.mts`（新增）

`desktop-test` 现在用 `await import()` 直接引用守卫，TypeScript 需要类型声明——与
`download.d.mts`、`update-core.d.mts` 的既有做法一致。

**没有改的东西**：`shared/asset-guard.mjs` 一行没动。1.6.2 修掉的「文件名穿越」
和「镜像白名单」原样生效（下面的测试照常验证）。

## 四、让这类事故不可能再漏测

### 1. 新增 `scripts/electron-load-check.cjs`（真的把主进程加载一遍）

用 stub 顶掉 `electron`（`app` / `ipcMain` / `Menu` / `shell` / `dialog` / `BrowserWindow`，
`app.whenReady()` 永不 resolve，所以不建窗口、不起服务器、不联网），然后 `require` 真正的
`electron/updater.cjs` 和 `electron/main.cjs`。任何机器（没有 Electron 二进制也行）都能跑：

```
  ok   the updater module loads in the main process
  ok   the main process entry point loads
  ok   a plain asset name survives the guard
  ok   a path in the asset name is still refused
  ok   the official asset URL is still allowed
  ok   a mirror prefix is still allowed
  ok   a mirror wrapping another host is still refused
  ok   the ES-module guard is not loaded through require()
electron-load ok (8)
```

最后一条很关键：**守卫必须不是经 `require()` 加载的**。因为 Node ≥ 22 会放行 `require(esm)`，
这条断言让「本地开发机看着没问题、装到用户机器上崩」这种情况也藏不住。

### 2. `desktop-test` 增加两条检查（17 → 19）

- **静态扫描**：`electron/`、`shared/`、`server/`、`scripts/` 下所有 `.cjs`/`.js`，
  命中 `require('…​.mjs')` 即失败；
- **实际加载**：`spawn` 上面的 `electron-load-check.cjs`，Node ≥ 22 时带
  `--no-experimental-require-module`（恢复 Node 20 的规则，等于复现用户看到的崩溃）。

### 3. CI 在打包前加载主进程

- Windows 与 macOS 两个 job 的「Type-check and test」都追加了
  `node scripts/electron-load-check.cjs`——不需要构建、不挑平台，就能证明主进程能加载；
- Windows job 另外在「Build the game」之后、「Package」之前跑完整的 `npm run test:desktop`
  （19 条，含静态扫描与 dist 服务检查）。

macOS job 没有跑完整 `desktop-test`：那一步要在 CI 里真的起一个绑定 `0.0.0.0` 的局域网服务，
一旦系统弹防火墙确认框就会挂住整条发布流水线，而它要验证的东西（主进程能否加载）上面那条已经覆盖。

### 反向验证

把 `electron/updater.cjs` 换回 1.6.2 的 `require` 版本，实测：

```
  FAIL no CommonJS file requires an ES module — electron/updater.cjs: require('../shared/asset-guard.mjs')
  FAIL the main process loads (updater.cjs + main.cjs) — ERR_REQUIRE_ESM require() of ES Module
       /home/user/TankGame/shared/asset-guard.mjs from /home/user/TankGame/electron/updater.cjs not supported.
desktop FAILED (2)
```

**和用户报的错误完全同一条**。换回修复版即 19/19 全绿。

## 五、已经装了 1.6.2 的人怎么办

1.6.2 的桌面版**连更新器都跑不到**，所以只能重装：

1. 到 [Releases](https://github.com/Adamisatree/TankGame/releases/latest) 下载 1.6.3 的安装包，
   覆盖安装即可（设置、地图库、已下载的历史版本都在 `%APPDATA%\TankGame`，
   覆盖安装不会丢）；
2. 不想等下载的临时办法：把新版的 `resources/app/electron/updater.cjs` 与 `main.cjs`
   复制到已安装目录的同名位置（管理员权限），重启。两个文件之外什么都没变；
3. 只想单机：`TankGame-1.6.3-portable.html` 双击即玩，不受这个 bug 影响（网页版没有主进程）。

## 七、兼容

应用版本变了，服务器的版本闸门按版本号比对：**1.6.2 与 1.6.3 不能联机**（协议格式仍是 v11）。
1.6.2 的桌面端本来就起不来，请直接和朋友一起升级到 1.6.3。

## 八、真机自查（这一版最该做的一条）

**装一次、双击一次再打标签。** 具体：

1. 安装 1.6.3 → 双击桌面图标 → 窗口正常出现（这是本版唯一的核心验收点）；
2. 菜单 →「更新与版本」→ 检查版本显示 `v1.6.3`、镜像列表正常、下载进度条能走；
3. 局域网联机：房主建房、访客加入（两边都是 1.6.3）；
4. macOS 上同样双击一次（右键 → 打开）。
