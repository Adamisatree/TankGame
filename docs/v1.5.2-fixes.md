# v1.5.2 · 紧急修复记录（退出 / 乱斗开局 / 多人团队开局）

这一版只做三件事，三个都是**线上能立刻遇到的问题**，所以单独发了紧急版。
约定同前：每条写清「原来什么样、改成了什么样、怎么验证」。

---

## 一、一个人退出不再结束整局

| 项目 | 以前 | 现在 |
|------|------|------|
| 触发 | 任何人退出 → 服务器广播 `surrender` → 房主 `handleSurrender()` → 整局直接判「投降」，**其余所有人都被结算** | 服务器仍然通知「有人走了」，但房主改成 `seatLeft(by)`：只处理这一个座位 |
| 公告 | 无名字的「对手离开了」，还会盖掉别的提示 | 弹一次「**P3 退出了游戏**」（带座位名），之后不再重复 |
| 对局 | 立刻结束 | **继续打**。走掉那位的坦克从场上移除，他的复活排队、输入、开火冷却一起清掉 |
| 只剩一个人 | 无（整局早就结束了） | 房主判他赢：公告 + 结果卡「你赢了」，原因 `left` |
| 团队模式 | 同上 | 按**队伍**判：只剩一支队伍时才收尾，剩下的那队全员赢 |
| 房主自己退出 | 客机停在原地等一个永远不会来的快照 | 客机弹「房主离开了房间，这一局作废」并出一张 `本局作废` 的卡（`host-left`），不判输赢 |
| 重连 | — | 走掉的座位在 `syncRoster()` 里会从 `goneSeats` 里摘掉，回来还能打；`loadLevel()` / 再来一局都会清空这份名单 |

相关代码：`src/game/GameScene.ts` 的 `seatLeft()` / `checkLastStanding()` / `checkLeftSeat()` /
`goneSeats`；协议里 `MatchResultPayload.reason` 新增 `'left'`、`'host-left'`
（`src/net/protocol.ts`、`src/game/events.ts` 同步）；结果卡文案在 `src/main.ts`。

**倒计时里也有人走**：`updateMatch()` 以前只在 `phase === 'playing'` 时才检查，1.1 秒的
「准备」阶段走人就没人管了。现在 `'ready'` 阶段也检查同一个宽限计时。

**「等待对手加入…」不再插队**：有人退出时 LAN 客户端会把状态退回 `waiting`，
`onStatus` 曾因此再弹一次横幅，把「P3 退出了游戏」盖住。现在对局中不显示这条。

## 二、乱斗（FFA）点开始没反应 —— 修好了

**根因**：房间界面的「开始对局」按钮按「有没有空队伍」来置灰。

- 乱斗里所有人都在 0 队，剩下 1～5 队**永远是空的**；
- 而 `startRoomMatch()` 只在团队模式才检查空队伍；
- 结果就是：按钮一直是灰的，点不动，乱斗**根本开不了局**。

**改法**：新增纯函数 `roomStartBlockers()`（`src/game/rules.ts`），
`mode !== 'team'` 时 `emptyTeams` 恒为 `[]`；`GameScene.emptyTeams()` 同样加了这个判断
（防止别处再踩）。按钮改为由 `emptyTeams.length || mapPending` 决定，
自定义地图还没同步完时仍然正确地拦住。

**验证**：`npm run smoke` 里新增 4 条断言（乱斗永远不被空队伍拦住 / 团队模式空队伍仍拦住 /
三队都有人可以开 / 地图没同步完仍拦住）；`scripts/probe-team.ts ffa 8` 实测
`emptyTeams []`、`startRoomMatch` 1 ms 进入 `playing`。

## 三、多人团队模式「一开始就卡死」

**根因：所有人出生在同一个点。** 出生点表里只有 4～6 个坐标，10 个座位挨个
`chooseRespawn()`，超出的座位全都落回同一个「安全点」。实测 10 人房：

```
p1@640,615  p2@640,141  p3@640,615  p4@640,615  p5@640,615  p6@640,615  p7@640,615 …
```

十台坦克叠在一格里 → 每帧的互相分离把它们往反方向推回去 → 原地抖动、谁也走不动，
看起来就是**开局卡死**（只有一台能勉强挪开）。团队模式更容易撞上，因为队友默认挤在同一侧。

**改法**（都在 `src/game/GameScene.ts`）：

1. `pickSpawnFor(team)` + `placeSpawn(x, y, radius)`：拿到推荐出生点后，
   以 `TANK.radius * 2 + 6` 为间距向外一圈圈找空位（16 方向 × 16 圈），
   同时要求 `spawnClear()`（不卡墙、不卡木箱）；
2. `chooseRespawn()` 新增可选 `isFree` 回调：优先从未被占用的出生点里挑，
   全都占满时退回完整列表（**永远不返回 null**，不会有人卡在「等复活」）；
3. 复活也走同一套：`scheduleRespawn()` 用 `placeSpawn()`，不再把复活的人塞进队友身上；
4. `separateTanks()` 补上完全重合（距离 < 1e-3）的分支：按座位对算出一个固定的分离方向，
   以前这种情况算不出方向，于是**永远分不开**。

**性能**：`placeSpawn()` 的搜索是有上限的（16×16 次矩形判定，每次只比存活坦克），
没有逐帧成本；10 人房首帧实测 2 ms、稳定 60 fps（见下）。

**验证**（真客户端，不是模拟消息）：

| 场景 | 结果 |
|------|------|
| 10 座团队房（同一进程内） | 10 个座位 **10 个不同坐标**（修复前 p3–p7 全在 `640,615`） |
| 6 座团队房（1 房主 + 5 个真客户端进程） | 每台客机都看到 6 台坦克、稳定 **60 fps**、0 运行时错误 |
| 走掉 1 人（6 座） | 横幅「P2 退出了游戏」，phase 保持 `playing`，坦克 5 台，其余人继续打 |
| 走掉到只剩一人 | `matchOver`，结果卡 `reason: 'left'`、`verdict: 'win'`、`winners: ['p1']` |
| 团队房走光一队（4 座） | 客机收到 `reason: 'left'`，`winners: ['p1','p3']` |

## 五、已知边界

- 房主退出时**没有**「换房主」：房间作废，客机回到主菜单重开房间。要接管房间需要一整套
  权威迁移（快照、时钟、地图确认都要换人发），不塞进紧急版。
- 走人的座位不会补 AI，人数自然减少，按剩下的队伍判胜负。
