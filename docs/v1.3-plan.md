## 三、现状 vs 目标

| 项 | 现状（代码） | 目标 |
| --- | --- | --- |
| 操作 | `SeatAction` 里有 `left/right`（底盘）和 `aimLeft/aimRight`（炮口 Q/E）两套；`applyInput()` 里 `turnHull()` 与 `aimAt()` 分两步，还会互相踩 | **一套转向**，炮口固定在车体上随车体转；鼠标或单键只做瞄准（见待确认 1） |
| 射速 | `fireCd = 0.24s` | 放慢，建议 **1.1s/发**（狂暴技能另算） |
| 攻角 | `TURRET_LIMIT = 72°`，只在代码里夹，画面上看不出来 | 画一段**扇形弧线 + 端点刻度**，明示可打范围 |
| 伤害 | `damage(victim, attacker, amount = 1)` 只扣 1 条命 | 按**命中部位**扣血：前 7 / 侧 9 / 后 12 |
| 生命 | 心形 × 3 条命（`lives`），`HIT_MERCY = 1.1s` 无敌 | 全员 **100 血 + 血条**，无敌帧取消或极短 |
| 反弹 | `BULLET.maxBounces = 4` | **2 次**（沿用上一轮要求） |
| 模式 | `solo` / `versus`（本地 2P）/ `lan`（**1v1 中继**） | 增加 **LAN 乱斗 2–6**、**LAN 团队**；本地 2P 保留 |
| 服务端 | `room = { host, guest }`，只配对两个人 | `room = { slots[], mode, team[], config }`，N 人 + 队伍 + 房间上限 |
| 胜负 | 命数打光 | 人头目标 / 时间上限 / 平局 |
| 地图 | 8 张单屏图（1280×720 固定 `PLAY_RECT`） | 新增**多人大地图**（世界大于屏幕）+ **坦克缩小** |
| 复活 | 复活在原出生点，无选择 | 乱斗：远离所有活人的随机点；团队：**队友身旁**，无队友则随机 |
| 友伤 | 无概念（1v1） | 开局前两个独立开关：友伤、自伤 |
| 技能 | 房主可改别人的技能（`skillP2 = skill`） | 每人自选，只在公示区展示 |

## 四、改动清单（按批次，可分别验收）

### 批次 1 · 操作、射速、攻角

- [ ] **1.1 合并转向**：`SeatAction` 去掉 `aimLeft/aimRight`（迁移旧存档：键位文件加 `version: 2`，旧 `aimLeft/aimRight` 丢弃）。
- [ ] **1.2 炮口跟随车体**：`Tank.turnHull()` 后 `turretAngle = bodyAngle + turretOffset`；`applyInput()` 只调一次转向，不再"先算瞄准角再转底盘"。**这修掉了按 A/D 时炮管钉在原地的老问题**。
- [ ] **1.3 射速**：`config.ts` 加 `FIRE_COOLDOWN = 1.1`（用常量，不散落在场景里），`fireCd` 读它。
- [ ] **1.4 攻角可视化**：在车体下方画一段淡墨弧线（±`TURRET_LIMIT`），两端带小刻度；瞄准到边界时弧线端点变红。
- [ ] **1.5 输入协议**：`TankInput` 去掉"世界瞄准角"，改为 `aim` = 相对车体偏移（或 `turn` + `aimTrim`），联机两侧算法一致。
- [ ] 测试：`selftest` 校验"底盘转 N 度后炮管相对夹角不变"、"Q/E 不再存在"、"射速间隔 ≥ 1s"。

### 批次 2 · 血量与部位伤害

- [ ] **2.1 血量**：`Tank` 加 `hp / maxHp = 100`；删 `lives`；`damage()` 改成 `hp -= amount`。
- [ ] **2.2 部位判定**：`bullet` 命中时按入射方向与车体朝向的夹角分类 → **前 ±60° = 7**、**后 ±60° = 12**、**其余（两侧）= 9**。
- [ ] **2.3 部位反馈**：命中处冒不同颜色墨点 + 伤害数字（7/9/12）；HUD 血条按 10 段刻度。
- [ ] **2.4 无敌帧**：`HIT_MERCY` 取消（或压到复活保护 0.8s，见待确认 3）。
- [ ] **2.5 反弹 2 次**：`maxBounces = 2`，AI 求解深度同步。
- [ ] **2.6 道具适配**：医疗包 **+40 血**；护盾「6 秒 + 只挡 1 次」，挡完立刻消失。
- [ ] **2.7 单人数值**：AI 也 100 血，难度改为调 AI 精度/反应/射速，不再调"敌人几条命"。
- [ ] 测试：`selftest` 部位伤害表、护盾一次消耗、医疗包上限、10 发打死。

## 五、需要你拍板的 5 个点

1. **"去掉转地盘和炮口"到底去掉哪一层？**
   - (a) **炮口彻底固定在车体上**：只有左右转向，车头朝哪就打哪（最干脆，配合车尾红点正好）
   - (b) **保留炮口可以在车体上偏转**，但只用鼠标瞄，不再有 Q/E 那套双键
   我倾向 (b)：能瞄又能保留"攻角范围"的展示意义；如果你要 (a)，那"攻角"就是 0°，弧线就没意义了。**选一个**。
2. **射速具体多慢**：1.0s/发（每分钟 60 发）还是 1.5s/发（每分钟 40 发）？配合"100 血 / 7–12 伤害"，1.0s 大概要 8–14 发打死一个人。
3. **无敌帧**：彻底删，还是保留"**复活后 1 秒**保护 + 受击无保护"？（建议后者，不然刚复活就被堵）
4. **复活要不要手动选点**：上一轮你说"死了可以直接选择复活到随机复活点"，这一轮团队说"复活在队友身旁"。我的方案是**自动分配**（乱斗挑远离活人的点，团队挑队友身旁），不弹面板。要手动选就得多一层 UI。
5. **团队复活在"队友身旁"**：是"紧贴队友（约 1 个车身）"，还是"离队友最近的安全点（可能在地图另一边）"？前者有堵人风险，后者更安全但可能很远。

## 十一、1.5.0（地图系统：编辑器 / 格式 v1 / 本机地图库 / 联机传图）

### 地图文件格式 v1（`src/maps/format.ts`）
- `format: 'tankmap'`，`schemaVersion: 1`，`id = custom-xxxxxx`，`rev` 每次保存 +1。
- 几何一律 0～1 归一化：`walls/crates` 是 `{x,y,w,h}`，`pickups` 是 `{x,y}`，`spawns` 是 `{x,y,angle}`。
- `size` 四档：单屏 1280×720 / 小 1800×1200 / 中 2400×1600 / 大 3200×2200；`w > 1400` 的图 `toLevel()` 会带 `world`，镜头随之滚动。
- `mirror ∈ none | rot180 | flipX | flipY`，**只画一半**，`applyMirror()` 在对局时补齐另一半（重复的自动去重）。
- `canonicalMap()` + FNV-1a `mapHash()`：用来判断「同一张图的两份副本是不是同一个版本」。
- `normalizeMapFile()` 永不抛异常：未知字段进 `extra`（新版本存的图老版本也能开、再存回去不丢），
  越界坐标夹回 0～1，缺出生点补齐两个（只缺一个就补一个，保留原来那个）。
- `validateMap()` 报错：`spawns`（<2 个）、`spawn-wall`、`spawn-crate`、`spawn-edge`、
  `spawn-face-wall`（出生点正对墙，开局打不出去）、`pickup-wall`、`pickup-crate`；
  警告：`empty`、`busy`、`tiny-wall`、`pickup-edge`、`crate-wall`、`newer`、`no-pickups`。

### 本机地图库（`src/maps/store.ts`）
- `localStorage['tankduel.maps'] = {version:1, maps:[…]}`，上限 **200 张**，全部读写包 try/catch（隐私模式不会炸）。
- `saveMap()` 保留 `createdAt`、`rev` 自增、合并 `extra`；`archiveReceived()` 收下别人的图但不动它的 `rev`。
- 导入 / 导出：`exportMapText()`（2 空格缩进）、`exportFileName()` → `<名字>.tankmap.json`；
  `importMapText()` 同时接受单张图和 `{maps:[…]}` 打包文件。

### 注册表（`src/maps/registry.ts`）
- `levels()` = 内置 + 自定义（缓存，存盘后 `refreshLevels()`），`levelIndexOf()` / `levelById()`。
- 随机选图默认只在**内置图**里摇（`randomLevelIndex()` 的 `pool = 'builtin'`），避免自定义图影响单人 5 连关节奏。
- `GameScene` 里 7 处 `LEVELS[...]` 全部改走 `levels()`，联机快照的 `level` 也按新列表解释。

### 编辑器（`src/ui/mapEditor.ts` + `.editor*` 样式）
- DOM + Canvas：40×24 网格，工具 墙 / 木箱 / 道具 / 出生点 / 橡皮；拖动时把同一行连续格子合并成矩形。
- 撤销 / 重做 60 步（快照含尺寸与镜像）、网格开关、清空、出生点朝向 ↑→↓←、出生点上限 10。
- 镜像在对局时生效，编辑器里用虚线画出镜像后的另一半（灰墙 / 棕箱 / 空心道具圈），**所见即所得**。
- 右侧栏：尺寸下拉、镜像、实时统计、逐条检查结果；底部：保存 / 保存并试玩 / 另存副本 / 导出 / 删除 / 导入。

### 联机传图（协议 v7 → v8）
- 房主把自己的自定义图随 `join`（或 `{t:'map'}`）推给服务器；服务器缓存 `room.map/mapHash`，晚进的访客也能拿到。
- 访客 `LanClient.takeMap()`：`normalizeMapFile` → `archiveReceived` 存进本机库 → 用 `mapHash` 校验 → 回 `{t:'map-ack', id, rev, hash, ok}`。

  哈希不对/存不下来回 `map-failed` + `detail`。房主收到 `{t:'map-status', waiting, ready}` 后刷新房间进度。
- 房间界面新增一行地图信息：「地图 · 名字 · 房主自建/内置 · 地图确认 1/2」；未确认时「开始对局」禁用。
- 开局改由服务器的 `begin` 触发（房主也不再自己跳进对局），`begin/start/restart` 都带 `levelId`，
  访客按 **id** 而不是下标找图（两边的自定义图顺序本来就不一样）。
- 传输上限 48 KB（`MAX_MAP_BYTES`），超过直接 `map-failed`，不会把一大坨数据塞进房间。
- 房间换了新地图（`rev`/哈希变化）→ 清空 ack，重新确认一遍；房主离开/重连时服务器丢弃上一张图，避免串房。

### 十一·补充：瞄准线跟着反弹次数走（1.5.0）

旧的瞄准线写死 `for (b = 0; b <= 4; b++)`：不管 `maxBounces` 是几，它都画 4 次反弹（5 段），
于是会出现「线拐了四道弯，炮弹第三次撞墙就没了」的错位。

- 新增内测旋钮 **`aimBounces`（瞄准线反弹，默认 2，0–6，步长 1）**，只影响那条虚线，不改真实物理；
- 逻辑拆成 `aimPreviewBounces()`（读取 + 夹取）和 `aimPreviewLegs(tank)`（纯几何：每段起点/终点 + 该点是否真的反弹），
  `drawAimGuide()` 只负责画——所以可以在 smoke 里断言段数和反弹点数；
- `aimBounces = 2` → **3 段虚线 + 2 个反弹点**；`0` → 一条直线；上限夹到 6。最后一段停在「炮弹会死的那面墙」上；
- 顺带修了一个老问题：**瞄准线以前会穿过木箱**（真实炮弹会被木箱吃掉）。现在撞到木箱就断线，且不画反弹点；
- 淡出按段数比例计算，段数多了也不会糊成一片。
- `npm run smoke` 66 → **83** 项：默认 2 次反弹、4 次、0 次、越界夹取、重置，以及「线不会比设定值拐更多弯」。
