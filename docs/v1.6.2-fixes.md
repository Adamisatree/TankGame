# 1.6.2 —— 联机稳定性 + 安全

1.6.1 之后做了第三轮审查（服务器全文、客户端联机段、大厅/规则、桌面/更新/地图四路），
一共 **49 条**发现。这一版把它们**全部处理**：41 条在上面的代码里修掉，另外几条
（下面标了「不改」的）是审查本身的环境假象或设计决定，写清理由。每条都配了能复现的
自动化检查——**把修复放回去，那条检查就会红**（下面有实测记录）。

---

## 一、P0：能让对局瞬间作废、让服务器崩溃的四条

### A-1 任意设备一条消息终结任何对局（伪造「房主投降」）

```js
// 旧代码
if (msg.t === 'surrender') {
  broadcast({ t: 'surrender', by: ws.playerId ?? msg.by ?? 'p1' }, ws);
```

没 join 过的 socket 的 `playerId` 是 `null`，于是 `msg.by` 由发送者随便填；
填 `'p1'` 之后每个访客都收到「房主投降」→ 走 `seatLeft('p1')` → 弹「房主离开了房间，这一局作废」。
局域网里任何一台设备（含旁观者）都能做到。

**现在**：只有真正坐在座位上的人能投降，`by` 只取服务器自己记录的 `ws.playerId`。

### A-2 被顶替的旧 socket 保留全部权限

房主刷新页面 → 新 socket 拿到 `p1`，旧的只收到一条 `replaced`，`role`/`playerId` **照旧**：

- 旧房主继续 `state`（假快照混进真实流）、继续 `config`/`teams`/`begin`（改房间）；
- 旧访客继续 `input`（和重连后的新主人同时开同一台坦克——「顶号」的网络层版本）；
- 旧 socket 正常回 pong，心跳永远不会清掉它，窗口是**无限长**的。

**现在**：`retire(oldWs)` 一句话把 `playerId`/`role`/`session`/`ready` 全部清空并标记不存活；
客户端收到 `replaced` 也会主动断开并提示「这个座位已在别处重新连接」（双保险）。

### A-3 畸形网址打死整个服务器

```
GET /%      →  decodeURIComponent 抛 URIError
            →  这个 throw 发生在未 await 的 promise 里
            →  unhandledRejection → Node 默认退出进程
```

而且请求永远不返回。实测：旧代码下 `lantest` 直接以 `URIError` 退出（下面的证据）。
Electron 主进程没有自定义 handler，同样会崩。

**现在**：解码包在 try/catch 里，坏请求回 400，服务器继续服务。

### A-4 「开始对局」永久置灰（地图确认幽灵）

房主推送自定义地图时，`mapWaiting` 记下当时所有非房主座位；访客离开只触发 roster，
**不触发 map-status**，于是：

- `mapPending` 一直为 true → 开始按钮禁用；
- 「重发地图」按钮要求 `total > 0`，欠确认的那位已经不在了 → 按钮根本不出现；
- 没有任何提示文案（提示只解释空队）。

服务端其实早就 ready 了（`mapPending()` 是实时算的），只有房主客户端卡死，直到换图或来新人。

**现在**：① 客户端 `syncRoster` 按现存座位修剪 `mapWaiting`/`mapReady`；
② 服务端在有人离开时重发 `map-status`；③ 大厅按在场人数算 `total`。

## 二、P1：公平与体验

| 问题 | 旧行为 | 现在 |
| --- | --- | --- |
| **A-5 掉线重连 = 免费满血** | 重连新建 `hp=100, kills=0` 的坦克；被围攻时断网即回血，一次抖动丢战绩 | 房主按座位记住血量/战绩，重连继承；真正退场（宽限期到）即清空，不会被下一个坐这个号的人继承 |
| **A-6 幽灵自动开局** | 房主点过「开始」但地图没同步完 → 之后换图、地图确认完成的一瞬间**自己开局** | 换图（`setRoomLevel` / 推送新图）即清 `startPending`；自动 begin 只对当前这次推送有效 |
| **A-7 ESC 暂停不广播** | 面板暂停会推 `paused=1`，ESC 不推 → 访客看门狗依次提示「网络不稳」→「收不到房主数据」 | `togglePause()` 走 `setPaused()`，两条路径一致 |
| **A-8 暂停期加入 = 静默黑屏** | `if (!snap) return;` 在看门狗之前，访客一帧都没收到时看门狗永不运行 | 看门狗移到判空之前；房主暂停时有人加入会补推一帧（带 `paused=1`） |
| **A-9 地图按索引回退** | 房主报了 `levelId` 但本机没有 → 索引回退加载**另一张图**，两边各打各的，无任何提示 | 有 `levelId` 就不许索引回退，弹「地图不同步」并提示房主重发；索引回退只留给不带 id 的旧协议 |

| **A-11 同 token 双 socket 劫持座位** | 第二个 socket 被当成新访客拿新号，离开时用它覆盖 `sessions[token]` → 原主人下次重连被恢复到别人的座位并踢人 | token ↔ 座位一一对应（`tokenSeat`）：同 token 再来视为**重连**，直接拿回自己的座位；顺便修了恢复分支无条件发 `host: true` 的问题（房主不在时会进幽灵对局） |

| **A-13 版本闸门可绕过** | `ws.version &&` → 不带版本号的访客直接放行 | 缺失版本同样拒绝（`reason: version`） |
| **A-14 容量可缩到低于在线人数** | 显示「8/2」，之后新人永远被拒 | 收缩时回 `lobby-error: capacity` 并把容量抬到在线人数 |
| **A-15 乱斗自动分队写越界队伍** | FFA 下 `team = 座位序号`，8 人两队时出现 team 7 | FFA 一律 team 0 |
| **A-16 静态目录前缀碰撞** | `startsWith(DIST)` 让 `…/dist2/…` 也通过 | `DIST + sep` 前缀比较 |
| **A-17 close 顺序 / 心跳泄漏 / error 监听被摘** | 只关 wss，端口释放前仍接受连接（同端口重启 EADDRINUSE）；listen 失败不清 interval；listen 成功后摘掉全部 error 监听（运行期 accept 错误直接杀进程） | 先 `server.close` 再 `wss.close`；失败清 interval；保留常驻 no-op error 监听 |
| **A-18 `pair()` 发错对象** | `paired` 发给「第一个非 p1 玩家」，3 人房里发给别人 | 只发给刚加入的那位 |
| **A-19 结果卡指错人** | `surrenderBy` 取 `goneSeats` 里**最早**离开的那位 | 取刚刚离开的那位 |
| **A-20 房间状态是模块级共享** | 同进程第二个 `createLanServer()` 与第一个共享房间（审查里 4 项「假象失败」正来自此） | 房间/水位/计数器全部搬进实例闭包；`/info` 也是每实例 |
| **座位号回退** | 9 个座位都被会话保留时回退发 `p11`（无配色、无输入路由） | 满员直接 `reject: full`，座位号恒在 p2–p10 |

## 四、大厅 / 规则（C 组）

- **C-1 内测面板监听器指数堆积**：每次「恢复默认 / 导入参数」都会重新绑定，
  而 `恢复默认`、`导出`、`展开` 从不被重建 → 每点一次翻倍（2、4、8…）。实测旧代码
  点 3 次执行 **21 次**处理函数。现在每次绑定先解绑上一次的（显式 detach 列表，
  不用 `AbortController`——测试里 jsdom 节点与 Node 的 AbortSignal 不同源）。
- **C-2 团队赛同帧达标按坦克顺序定胜负**：改为并列获胜（与 FFA 一致），且结果与行序无关。
- **C-3 三处 `matchHasEnder` 报警是死代码**：`setMatch` 改为「已自动打开默认人头目标」的提示，
  大厅开始按钮处的死分支删除（场景里保留最后一道防线，用于外部来的房间配置）。
- **C-4 加队按钮发送未 clamp 的 `teams+1`**（双击瞬时 7 队）：发送前 `Math.min(6, …)`。
- **C-5 服务器 `teams` 注释与实现不符**：按实现改正（加队只 clamp，填人是 `fill-teams`）。

## 五、桌面端 / 更新器（D 组，安全向）

- **D-1 局域网可达的下载→执行链**，四处一起修：
  1. 更新面板把 `version`/`asset.name`/`sha256`/`publishedAt`/来源直接拼 `innerHTML` → 统一转义；
  2. `asset.name` 当路径用（`..\..\evil.exe` 写出版本目录）→ `safeAssetName()`，只接受纯文件名；
     `install-file` 前缀检查改在 `path.resolve()` 之后并拒绝 `..` 段；
  3. 白名单只校验域名，镜像前缀可包装任意主机 → 要求整条 URL 是「官方发布地址」或「镜像前缀 + 官方发布地址」，
     重定向落地地址也复核（`allowFinalUrl`）；
  4. UDP 广播里的房间名原样拼 `innerHTML` → 转义，并校验端口范围、名字长度/控制字符、按 `host:port` 去重。
- **D-2 同 id 空地图覆盖本地地图**：`archiveReceived` 先做内容校验（`looksLikeMap` + 至少 1 面墙 + 2 个出生点 + id 合法），否则拒收。
- **D-3 `cachedManifest` 无写入者**（镜像测速永远测错上游）：`update:check` 成功后写回。
- **D-4 预发布版本字典序比较**（`beta.10` < `beta.2`）+ `parseInt` 接受尾部垃圾：改为按 semver 逐段比较、数字段严格解析。
- **D-5 sha256 未校验格式**（脏值让所有镜像报 mismatch）：只接受 `^[0-9a-f]{64}$`。
- **D-6 双击安装双 spawn**：加 in-flight 锁。
- **D-7 settings 并发写丢更新 / 非原子**：串行化 + 写临时文件再 rename。
- **D-8 `localIPv4` 取第一个私有地址**（WSL/Hyper-V/VPN 的 172.x 常排前）：先按默认路由找接口，找不到再回退旧逻辑。
- **D-9 UDP 扫描**：端口范围校验、名字清洗、按 `host:port` 去重（原来按 `name:port`，同名真机会被折叠）。
- **D-10 地图哈希 32 位 FNV-1a 可构造碰撞**：升到 64 位（同步实现，避免 WebCrypto 的异步改造）。
- **D-11 地图库按张数不按字节 + 接收失败原因统一误报**：增加 `MAX_LIBRARY_BYTES`（3.5 MB）字节上限；
  `takeMap` 区分「不是地图文件 / 库满了 / 存不下 / 校验失败」。
- **D-12 导入地图 id 无格式约束；`levelIndexOf` 未知 id 钳到 0 让判断失真**：id 必须是纯标识符否则重新生成；
  房间选图改用 `levels().some(...)` 判断。

## 六、明确「不改」的三条（审查报告本身的前提有误）

1. **A-12 的「服务器不检查 ready」**：准备状态在大厅是**建议性**的——房主点「开始对局」时
   客户端已经拦下未准备的人（`#lobby-start` 会列出谁没准备），开始权属于房主。
   服务端再拦一次会在名单广播还没落地时拒绝一次正常开局，因此保留现状并加了注释说明。
2. **审查报告 S7/S11/S12/S14 的失败**：报告自己也指出这是「多服务器共享模块级房间」的审查环境自伤。
   本轮把房间搬进实例闭包（A-20）后**这类假象不可能再出现**，并不是游戏逻辑的 bug。
3. **A-19 的「结果卡指错人」与既有规则**：只改「谁离开导致结束」的署名，不改 v1.5.2 定的
   「只剩一方才结束」的判定逻辑。

## 八、兼容

线上格式与协议版本未变（仍是 **11**），但应用版本变了：服务器的版本闸门按版本号比对，
**1.6.1 与 1.6.2 不能联机**，请和朋友一起更新（更新面板可以一键装，降级也行）。

## 九、真机自查（建议）

1. 三个人开一局，中途让一个人**被围攻时断网重连** → 回来还是残血，战绩没清零；
2. 房主按 **ESC** → 访客看到「房主已暂停」，不是「网络不稳」；
3. 房主推送一张自定义地图，欠确认的人**直接退出房间** → 房主「开始对局」立刻可用；
4. 房主换一张图再确认完 → 不会自己开局，必须再点一次；
5. 同一台机器开两个窗口用同一个房间 → 不会多出一个座位，也不会互相顶号；
6. 桌面端更新面板里，从镜像下载 → 文件名与 sha256 正常显示，进度条走完后才开始安装（双击只装一次）。
